# Корпус публичных высказываний — исследовательский проект (2026)

Независимый учебно-исследовательский проект по анализу публичных текстов **Дональда Трампа, Владимира Путина и Владимира Зеленского**. В первой версии: **только материалы с 1 января 2026 года** до даты исторической выгрузки. **Реального времени, расписания и фонового сбора нет.** Основной язык сайта, документации и пользовательских отчётов — русский; языки оригинальных текстов сохраняются.

Проект не является официальным сайтом МГИМО и не представляет администрации перечисленных политиков.

## Что уже есть

- Сборщик: `corpus2026/sources.py` (Truth Social через архив CNN, стенограммы Кремля, речи президента Украины и публичные Telegram-превью).
- Хранилище: `data/2026/*.jsonl`, оригинальные URL, дата, канал, тип текста, атрибуция, контроль дублей.
- Исторический отчёт: [`data/2026/run_report.json`](data/2026/run_report.json) — **единственный источник статусов полноты/ошибок**.
- Статический сайт: [`docs/index.html`](docs/index.html), [`docs/app.js`](docs/app.js), [`docs/style.css`](docs/style.css), [`docs/assets/mark.svg`](docs/assets/mark.svg), [`docs/method.html`](docs/method.html). Работает как файлы GitHub Pages, без сервера и GPU.
- Встроенная интерактивность: выбор политика и дат, фильтр источника, динамика публикаций по неделям, источник × политик × жанр, поиск по документам, **лексический сдвиг (log-odds с априорной регуляризацией)** по двум половинам выбранного периода; страницы с оригиналами.
- Аналитика: `corpus2026/topic_model.py` — экспериментальная регуляризованная PLSA (часть ARTM-подхода) + контрольная NMF, когерентность NPMI, разнообразие ключевых слов, помесячные распределения; CPU-only.
- Исследования: [`research/аналоги.md`](research/аналоги.md) и [`research/тематические_модели.md`](research/тематические_модели.md).

## Аудит и дозагрузка недостающего периода Telegram

Однажды (без расписания) выполняется `.github/workflows/telegram-gapfill-audit-2026.yml`:

1. `python -m corpus2026.telegram_extend` продолжает историю канала Зеленского с самого раннего сохранённого `message_id` **только за 2026 год**, сохраняя промежуточные результаты раз в 20 страниц. При блокировке/лимите не пытается обойти ограничения и записывает причину в `data/2026/telegram_extend_report.json`.
2. `python -m corpus2026.cli build-site` пересчитывает файлы сайта. Исправлено удаление `docs/data/topics.json` при пересборке.
3. `python -m corpus2026.audit` подсчитывает даты, число найденных документов, пустые месяцы и разрывы, проверяет дубли/диапазон и создаёт `data/2026/audit_report.json` и `docs/data/audit.json`.
4. Страница `docs/audit.html` визуализирует результаты и подчёркивает **неподтверждённую полноту**. Даже достижение 1 января не заменяет внешнюю сверку с архивом платформы.

Локально: `python -m pytest -q`, затем `python -m corpus2026.audit --until 2026-11-07 --out docs/data/audit.json`.

Ни ежедневный сбор, ни real-time, ни GPU здесь не задействованы. Публикация нового текста из сторонних зеркал без изучения условий использования не выполняется. Для официальных речей рассмотрены вторичные публикации PublicNow, однако ссылки/идентификаторы нужно сверять с первоисточниками; текущая выгрузка стенограмм Кремля и официального сайта президента Украины остаётся недоступной с runner.

## Проверка ведомственных архивов и зеркальных копий

Однократный workflow `.github/workflows/official-source-probe-2026.yml` **не загружает тексты**: делает запросы к 5 официальным доменам/индексам с проверкой `robots.txt` и всех HTTP-редиректов. Результат — `data/2026/official_source_probe.json`, копия для сайта — `docs/data/official_source_probe.json`. Открытие страницы из браузера не равно машинной доступности с GitHub runner, а доступность не равна лицензии на републикацию.

Проверяем, можно ли читать украинский президентский сайт по официальному адресу без `www` и альтернативные официальные домены Кремля. Если сайт запрещает роботов, мы не обходим защиту. **PublicNow исключён из автоматизированных запросов**: его [условия](https://www.publicnow.com/terms-and-conditions/) запрещают автоматический доступ и повторную публикацию без предварительного письменного согласия. Обращения на английском не заменяют украинские оригиналы в стилометрии.

## Как посмотреть сайт локально

```bash
python -m http.server 8000 --directory docs
```

Открыть `http://localhost:8000`. Проект не использует серверный рендеринг, никаких аналитик, cookies или внешних шрифтов нет. Графики генерируются клиентским JavaScript, чтобы их можно было проверить по исходным данным. Вкладка «Темы» показывает результаты только при наличии `docs/data/topics.json`; она не придумывает демо-темы.

**GitHub Pages сейчас не активирован**: Settings → Pages → Deploy from a branch → `main` → `/docs`. Код готов, но публичный сайт нельзя считать размещённым до успешной активации Pages владельцем репозитория.

## Обучение тематической модели — вручную, без GPU

```bash
python -m pip install -r requirements-analysis.txt
python -m corpus2026.topic_model --data-dir data/2026 --out docs/data/topics.json --max-docs 1400 --topics 7 --iterations 30
```

На GitHub предусмотрен отдельный workflow **«Анализ тем корпуса — однократный запуск»** (`.github/workflows/topic-model-2026.yml`). При запуске обучает три независимых языковых модели, сохраняет `docs/data/topics.json` и сравнивает регуляризованную PLSA с NMF по NPMI. Это не BigARTM и не ITAR; подробности и ссылки на полные научные публикации в [обзоре](research/тематические_модели.md).

Для последующего модуля названий тем рассматривается **[groundkit](https://github.com/2001092236/groundkit)**: бесплатные LLM, резервирование провайдеров и проверка ссылок. Автоматические LLM-запросы в этой версии **отключены**, ключи не нужны, сырые данные не отправляются в сторонние API. Внедрение только после оценки допустимости и качества.

## Историческая дозагрузка за 2026 год — вручную

```bash
python -m pip install -r requirements-dev.txt
python -m pytest -q
python -m corpus2026.cli backfill --source all --since 2026-01-01 --until 2026-11-07 --max-pages 110
python -m corpus2026.cli build-site
```

Команда выше повторяет выбранный срез, может занимать время и завершаться с кодом ошибки при недоступности внешних сайтов. **Нет обхода CAPTCHA, блокировок и правил robots.txt.** Смотрите отчёт по каждой подсистеме; страница сайта не должна обозначать частичную выборку как «полный год».

В дальнейшем планируется собрать официальные тексты через разрешённые API, архивы и машинные выгрузки с сохранением разметки прямой речи. Отдельные копии и переводы одного события не будут считать как независимые публикации.

## Организация данных

- `data/2026/` — исходные JSONL, не база SQLite. Для первой версии достаточно файлов с Git-версированием.
- `docs/data/` — ежемесячные порции JSON и сводные показатели для статического сайта.
- `docs/data/topics.json` — выход тематического моделирования, если расчёт запущен.
- `run_report.json` — ошибки/ограничения выгрузки.

Нет доступа к приватным аккаунтам, скрытым каналам, персональным данным граждан. Условия использования и авторское право первоисточников требуют отдельной проверки перед вторичным распространением полного текста. Возможен переход к публичному слою из метаданных и URL, если права не допускают широкую публикацию текста.

## Дополнительный статистический метод

Во вкладке «Темы» работает сравнение **лексики двух половин выбранного диапазона дат** по политико-лингвистическому подходу Monroe–Colaresi–Quinn (2008), в браузере без серверных вычислений и API. Для этого нужно выбрать **одного** политика и интервал не короче двух недель; данные обеих частей должны быть достаточны. Используются частоты токенов, информативный Dirichlet prior и z-нормировка. Выявленные различия — гипотезы о языке сообщений, не выводы о личности или политической позиции. Токены пока не лемматизированы. Реализация: `docs/lexical-shift.js`, проверка: `node tests/test_lexical.js`. Подробнее: [обзор методов](research/тематические_модели.md).
