# ITAR-подобный эксперимент на политических публикациях 2026 года

## Что реализовано

Ссылка на полный текст: A. Gorbulev, V. Alekseev, K. Vorontsov, 2024, [Iterative Improvement of an Additively Regularized Topic Model](https://arxiv.org/pdf/2408.05840). Статья различает темы **T+** (качественные), **T−** (некачественные) и **T0** (промежуточные). Дополнительно к обычным регуляризаторам ARTM используются:

- **R_fix (формула 10)** — приближает новый столбец Φ к распределению ранее принятой темы; в M-шаге добавка равна τφ_old.
- **R_filter (формула 11)** — штрафует новые свободные темы за пересечение с ранее принятыми и отвергнутыми; на M-шаге добавка отрицательна и пропорциональна текущему φ.
- **Декорреляция и разреженность** — как в исходной регуляризованной PLSA.

Реализация в `corpus2026/itar.py` использует эти два типа регуляризаторов, но сверх них **жёстко сохраняет** ранее принятые столбцы. Поэтому это **самостоятельный ITAR-inspired pilot**, а не точная реплика исходного метода с мягкой фиксацией и не официальный BigARTM/TopicNet. Этот выбор явно отражён в выводах.

## Порядок эксперимента

1. Для каждого лидера формируем отдельный набор по его языку. Делаем одинаковое ограничение `max_docs=900` (стратифицировано по месяцам), словарь до 2400 терминов и исходную матрицу частот.
2. Обучаем регуляризованную PLSA с тремя инициализациями (11, 23, 37) и оцениваем NPMI для каждой темы.
3. 80-й и 20-й процентили NPMI исходных запусков задают предварительные пороги хороших/плохих тем, **по каждому языку отдельно**.
4. Выбираем лучшую исходную модель по числу тем выше порога и средней связности.
5. В 2–4 дополнительных обучениях сохраняем хорошие темы и штрафуем свободные за совпадение с уже найденными хорошими и плохими. Для проверки новизны используем Jensen–Shannon расстояние; уникальная хорошая тема увеличивает TopicBank.
6. Стабильность базовых инициализаций измеряем средним косинусным сходством столбцов Φ после оптимального сопоставления венгерским алгоритмом (linear sum assignment).
7. Записываем по каждому лидеру количество тем в накопленном наборе, динамику по раундам, слова тем, NPMI, среднее baseline-сходство и SHA-256 исходной JSONL.

## Чего не делаем и почему

- **Не сравниваем абсолютные NPMI между Трампом, Путиным и Зеленским**: разные языки, жанры и объёмы. Для Путина текущий источник — пресс-служба Кремля, а не личные выступления.
- Монотонный рост принятого набора тем задан правилом накопления; это ещё **не** доказательство повышения качества тем и не held-out валидация.
- Нет проверки у независимых политологов и лингвистов, нет лемматизации русского/украинского словарей, нет сравнения с официальной реализацией ITAR на равных гиперпараметрах. Все темы — **экспериментальные словарные направления**.
- Чужие тексты не отправляются в бесплатные LLM; groundkit может пригодиться позднее для генерации названий тем по небольшим словарям с последующей экспертной проверкой.

## Запуск без GPU

```bash
pip install -r requirements-analysis.txt
python -m pytest -q tests/test_itar.py
python -m corpus2026.itar --data-dir data/2026 --out docs/data/itar_experiment.json --topics 7 --max-docs 900 --iterations 22 --rounds 4
```

На GitHub workflow `.github/workflows/itar-pilot-2026.yml` выполняется **один раз при создании** или вручную, без расписания. Для анализа полного набора выступлений потребуется сначала получить разрешённые полные оригинальные тексты, а затем повторить обучение.
